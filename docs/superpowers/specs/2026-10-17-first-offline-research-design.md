- 日期：2026-10-17

## 1. 目标与边界

### 1.1 要回答的问题

> 某个交易所的价格突然低于其他交易所时，盘口、成交及跨所信息能否帮助区分“短时回归”与“继续下跌”？这种预测改善在保守交易成本下还有没有价值？

这是研究假设，不是已经成立的套利规律。先从向下偏离、做多回归的单方向研究开始，减少变量；后续再考虑双向策略、挂单接针和复杂模型。

已有数天数据足够开始流程验证和探索实验，不必等待采满两周；但数据体积不能证明事件数充足，更不能证明长期盈利。研究流程跑通后继续使用新采数据做前向检验。

### 1.2 已确认的用户要求

1. 采集与监控由原会话继续负责，本研究不重启、不暂停、不修改采集或上传。
2. 原始数据继续全量保留；不以研究范围缩小为理由减少采集频道或市场。
3. 仍限 USDT 现货与 USDT 本位永续，不要求采集范围取三所交集。
4. 不新增付费资源，不把大批数据经个人代理搬回；算力与传输位置使用现有资源另行确认。
5. 长任务后台执行、提供阶段进度；普通可逆问题自行处理，不阻塞聊天和原监控。
6. 本阶段不交易、不连接账户私有 API、不读取凭据内容。

### 1.3 本方案提出的首轮默认值

这些是供本次审阅确认的实验设计，不是用户曾明确指定的数值：

- 先处理连续 **6 小时**的主窗口，流程通过后扩至 12 小时，再到多天。
- 研究币种目标 **30 个**，覆盖高、中、较低活跃度；不只研究 BTC/ETH，也不为凑数纳入无有效数据的市场。
- 永续是第一轮研究的目标市场；对应现货作为可选特征，不模拟现货借币或跨所资金划转。
- 第一版使用规则、岭回归、浅层树模型；Transformer 在同一评估流程稳定后接入。
- 币种抽样、实例抽查和可设置随机种子的模型均固定 `seed=42`；具体库版本也进入实验配置。
- 简单策略盈利不是训练 Transformer 的前提；**数据与评估可信才是前提**。

具体代码事实：

- `normalize.main()` 会删除并重建指定输出目录；不能在已有研究产物上直接反复运行。
- v2 的行情行没有完整的 `run_id/conn/source` 身份；`chain` 是单次归一化内部编号，不能跨分片直接当全局键。
- 归一化的 `conn.detail` 排除了原始 `topics` 且截断文本，不能仅靠该表还原每个频道/市场的订阅覆盖。
- `verify.book_vs_bbo()` 会先把窗口内 BBO 全量装进内存；当前比较按文件内相邻行分组，需测试盘口事件跨批次/文件时是否仍完整。
- 当前 verify 对隔离行、损坏段主要是计数打印，最终成功状态不能直接作为研究数据合格证明。
- 跨所价格粗检使用各市场最后一条价格，不保证来自同一时刻，不宜直接用作研究期单位/价差验证。

上述是实施前置检查，不在本次写方案时修改。此前监控中的“零缺口”“延迟全来自交易所”等判断只作为排查线索，不能替代对冻结输入的审计。短窗口通过也不能推广为数天全市场通过。

## 3. 总体路线与取舍

三种路线中，选择第三种：

| 路线 | 优点 | 问题 | 决定 |
|---|---|---|---|
| 继续等待更多原始数据 | 不打扰采集 | 不会自动补齐研究能力 | 采集继续，但研究不等待 |
| 直接全量归一化并训练大模型 | 很快启动训练任务 | 输入与评估错误昂贵，结果难解释 | 不作为首步 |
| 小范围端到端验证，再逐步扩容 | 问题可定位，较低成本得到证据 | 首轮不代表全市场长期表现 | **采用** |

数据流：

```text
云端已封口原始分段（只读）
  → 固定清单 + 有界下载缓存
  → 输入审计 + 带来源身份的研究规范化
  → 质量区间 + 因果盘口回放
  → 事件索引 / 常态样本 / 特征 / 标签
  → 规则与小模型对照
  → 成本及延迟敏感性分析
  → 新采数据前向检验 → 扩大范围 / Transformer
```

不引入 Kafka、分布式集群、在线特征平台或复杂管理台。沿用 Python ≥3.14、PyArrow、Parquet、pytest；小模型阶段再加入 scikit-learn，依赖必须锁定。GPU 不是前两阶段的前提。

## 4. 输入冻结、窗口和币种选择

### 4.1 输入清单是唯一的数据全集定义

先列举云端封口文件的元数据，再下载选定窗口所需文件。不根据采集机上“目前还剩什么”判断数据完整性。

每次实验生成不可变 `manifest.json`，记录：

- `experiment_id`、创建时间、代码提交、规范化/特征/标签/执行模型版本；
- 每个文件的存储对象身份、相对路由路径、run、分段序号、长度、下载后 SHA-256；
- 内容扫描得到的首末时间、记录数、序号连续性、损坏状态；
- 选择期、主窗口、预热依赖、标签尾部、币种列表、筛选规则、随机种子；
- 时间戳类型、已知采集版本及来源依据；无法确认的版本记 `unknown`，不能只凭日期猜提交；
- 参数、输入清单摘要和输出校验摘要。

清单在下载校验和预扫描完成后最终冻结；下载中的临时清单不作为正式实验输入。此后改变输入必须生成新的实验 ID。

同名对象不等于同一文件；重复对象按身份和内容区分，冲突不得静默覆盖。校验和证明本次输入可复现，不证明交易所原本应发的数据都已采到。

### 4.2 时间窗口必须包含状态依赖

- 首个主窗口选最近已完整封口且可读的连续 6 小时，避开已知部署切换边界作为流程验证起点；再选较早异常窗口做负对照。选择规则写入清单，不把“挑了最干净的窗口”包装成总体质量。
- 主窗口之前留独立 **2 小时选择期**，用于币种活跃度分层与初始阈值估计，不用主窗口未来表现选币。
- 下载还必须向前补足产品元数据、同一 run/connection 的有效盘口快照与衔接增量；不能仅按文件名截取 6 小时。
- 向后补足最大标签期限与执行延迟；没有依赖时标记不可用，不伪造快照、不跨断线填补盘口。
- 预热所需历史可能超过 2 小时；超过资源预算就缩小本轮研究范围或推迟窗口起点，不破坏状态依赖。

### 4.3 币种范围

仅纳入资产身份已核对、选择期至少两个交易所有有效 USDT 永续记录的加密资产。排除传统资产、稳定币互换、杠杆代币及同名身份未解决的产品。

以选择期内去重后的成交名义额对候选币排名，分成三个活跃度层，每层固定种子抽取 10 个；不足则保留实际数量并披露，不用事后表现替补。币种映射须核对公开产品资料，不能将相同 ticker 自动视为同一资产。

三所数据都可使用，但每个样本只要求当时具备必要的有效目标市场和参考市场。现货缺席用缺失标记表示，不取消整个币种；这不是把原始采集改成取交集。

## 5. 数据审计与研究规范化

### 5.1 质量以“市场 × 频道 × 时间区间”为单位

输出三态：`valid`、`invalid`、`unknown`，附原因与原始来源。不能将未知填成有效。

| 检查 | 处理原则 |
|---|---|
| 文件缺失、损坏、raw 序号中断 | 保留证据及影响范围；无法定位到具体频道时扩大未知范围 |
| 重连、run 切换、订阅拒绝 | 对应状态失效；盘口必须重新锚定后才恢复 |
| 盘口更新序列 | 按交易所/产品实际协议核对；协议不保证连续整数时不硬套 `+1` |
| 重建 BBO 与原生 BBO | 同市场、同身份与可比更新号匹配，报告匹配率、覆盖率与不匹配实例 |
| 同名币、乘数、合约面值 | 按当时已知元数据换算；无法确认的资产不进入跨所特征 |
| 跨分片重复订阅 | 保留观测来源，在逻辑事件层去重；相同 ID 不同内容视为冲突 |
| 频道静默 | 区分真实低活跃与订阅失效；“没有成交”不自动判丢包 |
| 长间隔及报价陈旧 | 按频道计分布；连接在线不等于频道有覆盖，消息总速率也不能代替逐市场检查 |

覆盖率分母为窗口内按历史元数据应在交易的市场时长；元数据不明的时段单列。质量报告同时列出已知缺失、未知以及各筛选步骤淘汰数量，不能只展示通过的数据。

### 5.2 不改原始层；研究输出另起版本

研究输出采用独立 v3 schema，放在本次实验目录，不覆盖 v2：

- 行情行补齐 `source_stream/run_id/conn_id/raw_seq/event_id` 与原始文件定位；一个盘口事件的多档行共享事件身份，另有档位行序号。
- `chain` 仅在来源命名空间内有效；跨分片、跨 run 不拼接半个盘口。
- 保留完整的连接—订阅 topics 映射，而非截断字符串；旧原始日志缺少必要事件时记未知。
- 同一逻辑行情的多份观测保留来源映射；研究回放按当时首次有效可见的观测处理，不能事后挑延迟最小的分片拼“完美行情”。时间冲突或身份不明时隔离。
- 归一化及验证按有界批次读取；盘口事件不能因行组/文件切分而被拆成多个独立快照。
- 产品元数据按来源与有效时间使用，不能拿最后一版元数据回填全历史。

### 5.3 时间语义是独立验收项

必须区分交易所事件时间、记录的收包时间、完整消息可解码时间、盘口状态可用时间和策略处理完成时间。

现有 raw 路径将一次读取完成的多个帧关联到 `last_ts`。TCP 合并、TLS 记录边界、WebSocket 分片、接收积压和时钟跳变都需验证。**存在 `kw` 不代表已经证明每条消息的精确可用时间。** `m` 也不得未经核对就解释为同一消息的内核单调收包时间。

处理要求：

1. 保留原时间字段和时间戳来源；同源先遵守原始记录顺序，再按验证过的可用时间做跨源合并，不能用交易所事件时间倒排出更早可见的信息。
2. 盘口增量最早可用时间至少不早于它依赖的快照和完整消息可用时间。先到增量、后到锚定快照时，不得回写出提前可交易的状态。
3. 同时间戳按固定来源身份/序号排序，仅用于确定性回放，不声称知道真实微观先后。
4. 对 TLS/帧边界与积压做合成探针，并对冻结实数据检查异常时间簇、倒序和长尾。单靠 `w-E` 或一次 socket 队列采样不能给延迟根因定论。
5. 验证未通过时，允许输出带局限说明的秒级描述统计；不能发布可信的亚秒回测或跨所领先结论。降采样与增加固定延迟本身不能修复未知时间语义。
6. 不能从已有日志恢复的时间信息明确记不可恢复；若需要补采字段，另提采集侧变更，不在本研究会话擅自部署。

### 5.4 历史残缺段

只处理已经停止写入的稳定副本。第一轮默认排除 `.partial`；后续可单独恢复其中完整帧，并保留损坏尾部及缺失区间标记。恢复数据不混作无损数据，不删除或重新封口原始文件。

云端若缺少崩溃遗留的本地孤儿段，质量报告标记“尚未归档/未取得”；是否复制这些文件由采集负责方另行处理。

## 6. 因果回放、事件与训练样本

### 6.1 回放规则

- 目标盘口先独立重建；跨所参考只取决策时刻已可见的数据，使用向后 as-of 查询，不用最近邻或未来报价补齐。
- 必需状态断链时不发出交易样本；非必需特征缺失时同时输出值缺失与原因标记。
- 第一版报价新鲜度门槛为 **1 秒**，只代表是否允许参与本轮决策，不代表超过 1 秒就证明采集缺失；门槛敏感性另报。
- 完整历史回放与“只提供到 t 为止的数据”必须在 t 产生完全相同的特征和触发结果。

### 6.2 首版事件定义：在线可触发的向下偏离

对每个目标永续市场：

1. 参考价为其他交易所同一资产有效永续中间价的中位数，排除目标所；至少一个外部参考，记录实际参考所数量。参考组成变化时重新预热 60 秒，不能把参考源切换造成的跳变当成插针。
2. 相对偏离为 `d(t) = 10000 × (target_mid / reference_mid - 1)`，单位 bps。
3. 用过去 60 秒的偏离中位数去除正常基差：`residual(t) = d(t) - trailing_median(d)`；只用 t 之前的值，且必须有完整有效预热。
4. 各市场阈值由选择期固定：`threshold = max(20 bps, 3 × 1.4826 × MAD(residual))`。不足以估计的市场不触发事件并记录原因，不随测试结果调阈值。
5. 从未越界进入 `residual <= -threshold` 时触发；同一资产跨所共用 30 秒冷却。时间语义通过后按 100ms 决策网格评估；该网格是实验分辨率，不承诺真实 100ms 下单能力。

事件是“当时价格偏离”，不是“事后一定反弹的针”。没有反弹、继续下跌以及缺少最终标签的事件均保留在事件清单中。

另保留每个目标市场每秒一个常态决策样本，关联同一资产的跨所事件组。事件样本与常态样本分别报告；若训练抽样，记录抽样概率，评估仍恢复真实候选机会分布。

### 6.3 特征与标签

初始特征限制在可解释的小集合：

- 跨所偏离、过去 1/5/30 秒收益及偏离变化；
- 目标所价差、前 5/20/50 档深度及买卖失衡；深度不足时带覆盖掩码；
- 过去 1/5 秒主动买卖成交名义额及失衡；
- 其他所变化、对应现货偏离及数据新鲜度；
- 资金费/OI/强平作为后续增量特征，不作为首轮闭环的必需条件。

标签：未来 **1、5、30、60 秒**目标市场中间价收益，定义为 `y_h = 10000 × (mid(t+h) / mid(t) - 1)`，单位 bps；价格采用该时刻有效的向后 as-of 状态。另记期间最大有利/不利变动；事件额外记录偏离是否回到阈值内。首要预测任务固定为 **5 秒收益回归**，其余为次要分析，不从测试集挑最好看的期限当主结果。

标签窗口跨越缺失、交易中止或不可用盘口时，标为 `censored/invalid`，不把缺失收益填成零。报告这类事件的数量、当时特征和缺失原因，防止坏行情被筛掉造成幸存偏差。

### 6.4 可回放事件包

输出轻量 HTML/图表与 Parquet 索引，不先开发完整 Web 系统。每个实例展示目标与参考价格、盘口/成交、可见时间、触发点、标签窗口、质量状态及来源定位。

按事先固定种子抽取最多 30 个：回归、继续下跌、普通行情及数据异常均有；不足则如实报告，不挑几个盈利故事代替总体评估。

## 7. 规则、小模型与交易成本

### 7.1 对照组

所有组使用相同币种、有效区间、样本、切分和成本假设：

- A：无交易基线；预测基线为零收益及仅用当前偏离的简单模型。
- B：第 6 节固定偏离规则，不加事后选出的过滤器。
- C：岭回归预测 5 秒收益。
- D：浅层梯度提升树，使用同一特征集；只允许预先登记的小规模超参搜索。

模型预处理、填充值、缩放和任何特征筛选仅拟合训练集。非必需缺失特征带 indicator。交易过滤阈值仅在验证集选择，测试集不重新选择阈值、特征或持有期。

### 7.2 第一版只做保守的吃单估算

不做挂单排队模型，不把“价格触及”当成交。第一轮交易假设为单次做多、持有 5 秒后退出，不加杠杆、不加止盈止损优化：

- 触发到执行延迟分别用 **100/250/500ms**；250ms 为主情景，包含策略处理与订单到达的假设，不冒充实测延迟。
- 固定名义额 **100 USDT**，另测 500/2000 USDT 容量；按历史 tick/lot 和价格限制校验，不满足最小下单量则拒绝并计数。
- 买入按假设执行时点的卖盘逐档计算 VWAP，卖出按持有期结束并加退出延迟后的买盘逐档计算；深度不足不推算隐藏流动性。
- 每边手续费分别使用 **2/5/10 bps** 的假设情景，5 bps 为主情景；不宣称这是用户真实费率，不读取账户配置。额外每边 **0/2/5 bps** 不利滑点敏感性单列。
- 跨资金费结算时计入当时已发布的实际结算费率；缺少必要费率时该笔经济评估记不完整。
- 单资产同时最多一笔仓位，跨所触发按确定性到达顺序选择；不把同一冲击在三所计算成三份可无限复制的利润。
- 未成交、被价格限制拒绝、深度不足、退出数据缺失分别统计。已进入但无法估算退出的仓位保留为未解决敞口，不能从总结果中删除后宣布盈利。

这只是历史可见盘口下的执行近似，尚未完整模拟冲击、撤单竞争、拒单和账户限制。预测有效、扣费后估算为正、真实可成交是三件不同的事。

## 8. 切分、指标与结论纪律

### 8.1 时间切分与防泄漏

- 首个 6 小时窗口按时间 60%/20%/20% 分成训练、验证、测试，仅用于流程与探索验证，不称为长期样本外证据。
- 为每个样本记录完整依赖区间（最长回看 60 秒、最长标签 60 秒，以及执行延迟）；跨越任一切分边界的样本丢弃，不机械只留固定秒数。
- 同一资产的重叠事件窗口跨交易所归为一个事件组，不能被拆进不同集合；测试时同样防止把一根针的数百个窗口当数百次独立成功。
- 跨币同步冲击另报时间簇；按日/时间块评估，而非对逐条 tick 假设独立。样本天数太少时不报告伪精确置信区间或年化指标。
- 扩到多天后做滚动时间切分；锁定代码和参数后，把随后新采的至少一个完整 UTC 日作为首次前向检查。查看结果后再改模型，该日就不再属于未见数据。
- 不承诺“一天前向通过即证明有效”；根据独立事件数与行情覆盖决定继续积累，不设 TB 数门槛。

### 8.2 固定报告内容

1. 数据：各市场/频道 valid、invalid、unknown 时长，解析错误、重复、隔离原因、陈旧报价分布。
2. 样本：筛选漏斗、每币/每日/每所事件数、独立事件组数、被截尾标签比例。
3. 预测：首要任务 MAE、相对零收益基线改善、按时间块的相关性及分币/分所表现；恒定标签等不可定义指标显示 N/A。
4. 经济：触发/尝试/可估算成交/拒绝/未解决仓位数量，毛收益、手续费、价差与滑点后的收益、分组收益和容量敏感性。
5. 解释：规则与模型在相同机会集合上的增量，最差事件、盈利集中度；没有模拟资金/组合约束时不报账户 ROI。
6. 可复现：输入与配置摘要、代码版本、样本计数、随机种子；重复运行的语义输出一致。

若收益只来自单币、单次冲击或最乐观费用假设，结论写“脆弱/待验证”。零事件也是有效结果：报告数据覆盖及阈值条件，不自动放松测试阈值追求好看结果。

## 9. 产物与模块边界

实验数据统一放在已被 Git 忽略的 `data/research/<experiment_id>/`：

```text
manifest.json / config.json          固定输入和参数
normalized/v3/                      带来源身份的研究表
quality/intervals.parquet            三态质量区间与原因
quality/report.md                    全量筛选漏斗与审计结果
replay/events.parquet + examples/    事件索引与可视化实例
samples/                            特征、标签、依赖区间、切分身份
results/                            对照实验、敏感性和结论
```

预计模块职责（后续实施计划再落实函数接口）：

- `tick/research/catalog.py`：文件清单、校验、版本与依赖范围。
- `tick/research/quality.py`：频道覆盖和有效区间，不承担信号计算。
- `tick/research/replay.py`：来源隔离、事件归并、盘口状态与可见时间。
- `tick/research/dataset.py`：事件、特征、标签及因果切分。
- `tick/research/baseline.py`：规则/模型训练和预测，不直接访问 raw 或私有 API。
- `tick/research/evaluate.py`：预测指标、执行近似、敏感性及报告。

`tick/normalize.py`、`tick/verify.py` 的离线缺口按门禁优先补齐；共享逻辑改动必须通过原回归测试，并保证采集启动路径不引入研究依赖。采集模块不在本轮实施范围。

公开仓库仅放方案、代码、合成测试及不含部署信息的示例；不提交真实数据、完整会话、运行清单、云端对象标识或机器/认证配置。

## 10. 分阶段实施与验收门槛

| 阶段 | 工作与交付 | 进入下一步的条件 |
|---|---|---|
| P0 小输入验证 | 单个时间小片的清单、依赖闭包、转换耗时/内存/膨胀率；异常合成测试 | 时间/来源身份问题有结论；不破坏原始文件；资源预算可行 |
| P1 数据质量 | 冻结 6 小时窗口；流式规范化；覆盖及质量报告 | 入选样本依赖全部可追溯，无未解决的解析/单位/身份错误；不合格区间显式排除，未知保留 |
| P2 因果回放 | 事件索引、常态样本、质量掩码、可视化实例 | 截断未来不改变过去；不跨断链；抽查价格/盘口一致；有有效样本，零事件时允许停在统计结论 |
| P3 基线实验 | 规则、岭回归、树模型；时间切分；成本敏感性 | 所有组使用相同数据与假设；结果可复现，失败/未解决仓位完整披露；不以盈利为软件通过条件 |
| P4 扩窗与模型升级 | 多天滚动、前向检验、Transformer 冒烟 | P1–P3 的完整性和因果性门禁通过；资源预算确认；另写模型设计，不照搬未披露结构 |

每阶段完成即汇报，不把全部阶段合成一次漫长任务。本次文档批准后，先写 **P0–P1 的实施计划**；P2–P4 保留为路线，不提前大规模搭建。

### 必须覆盖的测试场景

- 缺中间段、同名不同内容、损坏尾部、稳定 `.partial`；空输入不能通过。
- 分片间重复 symbol、run 内连接重用、跨 run 相同 update ID；不得覆盖别的来源。
- 一个盘口事件跨行组/文件；快照前后次序、缺口重锚定、单位与产品身份变化。
- 连接正常但频道缺失；冷门币无成交；原始 topics 不在规范化摘要中；不得据此误报全覆盖。
- 收包合并、TLS 跨包、WebSocket 分片、相同时间戳、时钟回跳；不能把未验证时间解释成精确消息到达。
- 修改 t 之后的数据不会改变 t 的特征；标签/预热越过切分边界时被正确剔除。
- 同一冲击在多所重复出现，标签缺失、零事件、恒定预测、薄盘口、价格限制、无法退出。
- 在不同批次大小、文件枚举顺序下，输出逻辑事件/样本/指标一致；内存不随历史总行数线性增长。

## 11. 资源、运行与安全边界

- 原始数据只读；转换产物按实验 ID 隔离，完成后原子发布，不覆盖旧实验。
- 重跑以冻结文件/分区为单位，校验输入与配置一致后复用完整产物；不做复杂的逐消息检查点。
- 先用小片实测压缩输入→Parquet→样本的膨胀率、吞吐和峰值 RSS，再估全窗口预算；不能直接沿用早期 90 秒采集测速。原始段混有多个市场，只选 30 币不意味着下载量按币数等比例减少；预算按实际必需分段计算，尽早过滤只降低后续产物与计算量。
- 大计算不放采集机，不暂停上传给本研究“攒完整文件”；研究读取已归档对象。
- 处理位置、缓存预算和可用磁盘在实施前检查；默认只启一个处理 worker，余盘不足以容纳预算产物加 20% 余量时不启动批次。可回收的只有本地已校验下载缓存，绝不删除云端原件。
- 不搬完整 1TB 数据到笔记本，不经个人代理承担全量流量。若现有资源无法直连存储或空间不足，汇报最小资源缺口，不自动购买或换云。
- 所有长下载、转换和训练后台运行；阶段日志报告文件进度、数据区间、耗时、内存和错误，不打印认证材料。
- 不为研究读取凭据文件；需要新授权或付费资源时由用户决定。发现采集侧疑似缺陷只记录证据，协调原负责会话，不抢占其运维工作。

## 12. 自审与下一步

本方案的核心验收不是“训练跑起来”，而是：

1. 能说清输入究竟包含哪些时间、市场和频道，以及哪些内容未知或丢失。
2. 能证明特征只使用当时可见信息，失败/继续下跌的事件没有被排除在结论之外。
3. 能在同样的数据和成本假设下比较规则与模型，并由固定输入重现结果。

当前只完成方案编写和静态代码核对，**未下载研究数据、未运行转换、未训练模型、未验证采集历史质量**。

用户审阅此文档后，先将 P0–P1 拆成带具体接口、测试与资源预检的实施计划。新数据继续采集；即便首轮模型无效，也应得到可复用的数据审计与回放基础，而不是只留下一个无法解释的分数。
